# PICO General Agentic Tools Plugin Guidance

This installed plugin is the entry plugin for PICO development. `pico-cli setup` installs it once per user; project development then uses `pico-project-setup` to configure the matching platform plugin. Standalone knowledge, device, emulator, and capture work needs no project configuration.

## Plugin Guidance Overview

The plugin provides platform-agnostic agentic tools that are useful across all PICO development targets. Skills are not code libraries. They are host-loaded prompts plus bundled references.

Agents may read this file from a copied or linked project context. In that case, the current working directory is the user's application project, not the plugin source or marketplace root.

## Routing

- Once a project is configured, its platform plugin's `AGENTS.md` owns SDK/application routing. Shared diagnosis, emulator/device, screenshot, and camera tasks remain owned by general, including in Unity projects.
- `pico-project-setup` runs `pico-cli project detect` and `pico-cli project configure`. It never creates project files itself; it hands empty-directory creation to the platform plugin's creation Skill.

- For an explicit persistent knowledge-version change, use `pico-cli`'s knowledge-selection procedure; configure preserves existing pins. A temporary version-specific question stays with `knowledge-query` and does not authorize a persistent change.
- Standalone tools and SDK questions do not require project configuration. Use `knowledge-query` for SDK facts, and the matching shared Skill for device work.
- Strongly recommend the latest compatible CLI in the existing channel and matching plugins; preserve explicit pins and deferred updates. Before the first environment-dependent CLI, MCP, device, or capture operation in a session, use `pico-env-doctor` and inspect the complete report. Help/version discovery and static work are exempt. Reuse valid task-readiness evidence under that Skill’s session rule; emulator/device/app lifecycle changes refresh only their target-specific state rather than forcing the full doctor to repeat. Only task-required failures block work, and repairs require authorization.

- For operating an existing application or handling `INTERACTION_FRICTION_HIGH`, use `pico-app-interaction`. It is an atomic operation Skill alongside `capture-camera`; `pico-cli` retains command-usage guidance.

## MCP Guidance

- **`pico-spatial-editor`** and **`unity-mcp`** — User-level MCP servers declared by general, independent of project configuration. Discover their tools accepting hyphen/underscore Host normalization (`pico-spatial-editor` vs `pico_spatial_editor`, `mcp__` prefixed forms) and call exact advertised names. For `not-in-spatial-project`, pass the intended workspace for authorized non-coding Editor work; configure a platform only for project development. When Unity exposes only `get_unity_relay_status`, follow its initialization guidance, reconnect only `unity-mcp` using the Host's supported action, and verify native tools. First registration discovery remains Host-dependent; a full session restart is not the default repair. Host approval, project trust, and Editor readiness still apply.
- **`pico-dev-knowledge`** — Knowledge-graph MCP for PICO development, launched through `pico-cli knowledge:server`. It prefers the project's selected knowledge, otherwise the user-level selection. `pico-cli project detect --format json` reports the disk selection, not live server state. When the selected graph is unavailable, the server may use a usable user-level selection of the same platform. Its `graph_stats` note describes that startup fallback, not the live workspace after later switches. Follow `knowledge-query` and require a usable restore baseline before switching workspaces.
