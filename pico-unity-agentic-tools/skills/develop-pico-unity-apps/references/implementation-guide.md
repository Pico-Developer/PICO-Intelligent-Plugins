## Versions and Packages

The SDK 6.0.0 documentation snapshot provides these Unity baselines:

- PICO XR and Unity OpenXR: Unity `2022.3.15f1` or later.
- PICO Spatial: Unity `2022.3.62f2` or Unity `6000.0.59f2`.
- XR Interaction Toolkit 3.x is recommended for basic PICO XR interaction.

Do not determine compatibility from minimum Unity versions alone. Also verify:

- The installed PICO Unity SDK version and package source.
- Unity OpenXR Plugin, XR Interaction Toolkit, XR Hands, AR Foundation, and URP versions.
- Target PICO OS version and device model.
- Versions pinned by known issues, such as OpenXR Plugin 1.8.2 for subsampling, 1.10.0 for the `eyeTextureResolutionScale` crash, and 1.16.x for passthrough issues.

## Import and Configuration

1. Back up or commit the current project state.
2. In Package Manager, use **Add package from disk** and select the SDK's `XR/package.json`.
3. Restart Unity if Input System setup requests it.
4. Open **PICO > Portal**.
5. Select the target mode:
   - For PICO XR or Unity OpenXR, run **Apply All**.
   - For PICO Spatial, apply each item, including SpatialAdapter Runtime.
6. Open Project Validation:
   - Fix Required items first.
   - Evaluate Recommended items individually instead of overwriting product requirements blindly.
   - Enable Optional items only when the feature requires them.
7. After every mode change, recheck the XR Provider, OpenXR Features, scene components, and script namespaces.

## Minimal Scene for Each Mode

### PICO XR

- Import XR Interaction Toolkit Starter Assets. Import XR Device Simulator when Editor input simulation is useful.
- Keep one XR Origin, Main Camera, and Audio Listener in the scene.
- Add `PXR_Manager`.
- Use PICO Building Blocks for Controller Tracking, Canvas Interaction, or Hand Tracking.
- Use `ByteDance.PICO.XR`.
- Validate HMD pose, controller pose, a ray, and one interactable object before adding advanced capabilities.

### Unity OpenXR

- Import required OpenXR Plugin samples such as Controller, Meshing Subsystem Feature, and Intercept Feature.
- Enable the Android OpenXR Loader and PICO Support.
- Enable only the Interaction Profiles and PICO OpenXR Features required by the product.
- Use `ByteDance.PICO.OpenXR`; use `ByteDance.PICO.OpenXR.Editor` for Editor extensions.
- Validate the Controller sample or a minimal XRI scene before adding passthrough, body tracking, foveation, or other features.

### PICO Spatial

- Use `ByteDance.PICO.Spatial`.
- Use Spatial Camera and keep only one Spatial Camera in each Unity scene.
- Constrained enters Shared Space; Unconstrained enters Full Space.
- Configure Runtime, Play-to-PICO, and Exporter under `Project Settings > PICO Spatial`.
- Use EnhancedTouch/Spatial Input or XR Spatial Pointer Interactor. Do not assume ordinary mouse or touch semantics are equivalent.
- Do not instantiate GameObjects or Prefabs in `Awake()`; move creation to `Start()`.
- Re-export after reordering sibling objects in the scene hierarchy, and handle the project `temp/` directory according to the known issue.
- Do not change Collider types dynamically at runtime.
- Use Spatial Engine synchronization APIs for dynamic materials and textures. Do not assume `Material.SetTexture` synchronizes automatically.

## Android Baseline

Core Required checks from Project Validation include:

- Build Target: Android.
- Minimum API Level: API 29 or later.
- Scripting Backend: IL2CPP.
- Target Architecture: ARM64.
- Graphics API: Vulkan or OpenGLES3.
- Orientation: Landscape Left.
- Application Entry Point: Activity.
- Correct XR Provider.
- One XR Origin, Main Camera, and Audio Listener; apply Spatial Camera rules for PICO Spatial.

Common Recommended settings include:

- Target SDK: Auto.
- Color Space: Linear.
- Android texture compression: ETC2 or ASTC.
- Enable Multithreaded Rendering.
- Disable Graphics Jobs.
- Stereo Rendering: Multiview, unless a specific feature requires Multi-pass.
- URP Intermediate Texture: Auto.
- Disable URP SSAO.
- Use the recommended MSAA level.
- Enable Run In Background for Unity 6.
- Enable Optimize Buffer Discards with Vulkan.

Do not treat Recommended settings as absolute. AppSW, FFR/ETFR, URP, OpenGLES/Vulkan, and Multiview/Multi-pass have feature-specific combination constraints.

## Permissions and Manifest

PICO devices run Android. The SDK writes some metadata and permissions automatically according to enabled capabilities.

Principles:

- Prefer declarations generated by the SDK or Portal.
- Enable **Custom Main Manifest** only for additional requirements.
- Before editing, inspect `Assets/Plugins/Android/AndroidManifest.xml` and third-party manifest merges.
- Implement runtime authorization, denial, permanent denial, revocation, and fallback behavior.
- Never log tokens, accounts, keystore passwords, or complete connection credentials.

Common manual permissions:

- Network: `android.permission.INTERNET`, `android.permission.ACCESS_NETWORK_STATE`.
- Microphone: `android.permission.RECORD_AUDIO`.
- Camera or SecureMR Readback: `android.permission.CAMERA`.
- Vibration: `android.permission.VIBRATE`.

When eye tracking or face tracking is enabled, the SDK can inject the corresponding metadata and permissions. Do not duplicate or modify them unless the merged manifest is confirmed to be wrong.

## Lifecycle and Architecture

### Platform Boundary

Define product requirements through stable interfaces, for example:

```text
IEyeTrackingService
ISpatialAnchorService
IPassthroughService
IBodyTrackingService
```

Provide separate implementations for PICO XR, Unity OpenXR, and no-device environments. Avoid spreading compile symbols and SDK types throughout business scripts.

### Provider State Machine

Tracking and environment-sensing features should handle at least:

```text
Unsupported -> PermissionRequired -> Starting -> Running
Running -> Stopping -> Stopped
Any -> Error
```

Implement:

- Capability queries.
- Permission request and denial handling.
- Idempotent Start/Stop.
- `OnApplicationPause` and `OnApplicationFocus`.
- Scene unload and `OnDestroy`.
- Provider state and error-code logging.

### Coordinates and Data Contracts

- Define Tracking Origin and Local/Stage/View Space explicitly.
- Record whether a pose is raw, aligned, or world-space data.
- Do not silently swap axes, units, or handedness at the platform boundary.
- Changes to native shared structures, enum widths, texture handles, and similar boundaries may be ABI or data-contract changes. Do not treat them as ordinary C# refactors.

## Migration

Namespace mapping:

| Legacy namespace                       | Current namespace                   |
| -------------------------------------- | ----------------------------------- |
| `Unity.XR.PXR`                         | `ByteDance.PICO.XR`                 |
| `Unity.XR.PXR.Input`                   | `ByteDance.PICO.XR.Input`           |
| `Unity.XR.PXR.Editor`                  | `ByteDance.PICO.XR.Editor`          |
| `Unity.XR.PXR.SecureMR`                | `ByteDance.PICO.XR.SecureMR`        |
| `Unity.XR.PICO.TOBSupport`             | `ByteDance.PICO.Enterprise`         |
| `Pico.Platform`                        | `ByteDance.PICO.Platform`           |
| `Unity.XR.OpenXR.Features.PICOSupport` | `ByteDance.PICO.OpenXR` / `.Editor` |
| PICO Spatial                           | `ByteDance.PICO.Spatial`            |

Migration steps:

1. Record old package versions and prefab, scene, and asmdef dependencies.
2. Remove legacy PICO Integration or OpenXR packages.
3. If missing legacy symbols block import, add `ENABLE_PICO_XR_SDK` temporarily.
4. Import the unified SDK.
5. Migrate namespaces according to Runtime and Editor boundaries.
6. Handle API signature, enum, and lifecycle changes individually.
7. Check Missing Script references, serialized fields, and prefab overrides.
8. Run Portal and Project Validation.
9. Validate a minimal scene on a physical device before restoring product features.

## Acceptance Checklist

- [ ] The mode selection is backed by explicit evidence.
- [ ] Unity, SDK, package, device, and PICO OS versions are recorded.
- [ ] Portal configuration is applied.
- [ ] Project Validation has no Required errors.
- [ ] Android, IL2CPP, ARM64, and API 29+ are confirmed.
- [ ] The scene has no duplicate Origin, Camera, or Audio Listener.
- [ ] Sensitive capabilities handle permission denial and unsupported devices.
- [ ] Providers implement start, stop, pause, resume, and teardown paths.
- [ ] Editor, Emulator/preview, and physical-device validation boundaries are documented.
- [ ] Logs contain no keys, tokens, or signing passwords.
- [ ] Performance is measured on a physical device with PICO or Unity tools.
